# БД. ЛР №4 «Логическая и физическая модель БД» — краткая версия

## 1. Этапы проектирования
| Этап | Суть | СУБД учитывается? |
|---|---|---|
| **Концептуальное** (инфологическое, семантическое) | Анализ понятий предметной области | Нет |
| **Логическое** | Схема данных по модели (ER-диаграмма) | **Нет** |
| **Физическое** | Таблицы и SQL под конкретную СУБД (PostgreSQL) | **Да** |

**Проектирование БД** — выбор логической структуры для данных: какие нужны таблицы (отношения) и столбцы (атрибуты).

## 2. Главные термины
- **ER-модель** («сущность–связь») — графическое представление структуры БД. Состоит из **сущностей, атрибутов и связей**.
- **Сущность** — объект определённого типа (*Студенты*).
- **Атрибут** — свойство сущности (*фамилия*).
- **Связь** — соединение двух и более сущностей. Называется глаголом (*состоит из*).
- **Бинарная связь** — связь между двумя сущностями; самая распространённая.
- **Потенциальный ключ** — атрибут или набор атрибутов, **уникальный и неизбыточный**.
- **Первичный ключ (PK)** — выбранный потенциальный ключ; однозначно определяет запись. **Он один** на таблицу.
- **Альтернативный ключ** — остальные потенциальные ключи.
- **Суррогатный ключ** — искусственный атрибут **без смысла**, но уникальный (*код подразделения*, `SERIAL`, `UUID`).
- **Естественный ключ** — ключ со смыслом (*номер студенческого билета*).
- **Внешний ключ (FK)** — поле **подчинённой** таблицы, ссылающееся на PK **главной**.
- **Ограничение (constraint)** — правило, которое не пускает в БД некорректные значения.

## 3. Типы связей
| Тип | Пример | Физическая реализация |
|---|---|---|
| **1:1** | Студент — студенческий билет | Совпадение PK (PK одной таблицы = FK на другую) |
| **1:N** (самая частая) | Группа — студенты | FK в подчинённой таблице |
| **N:N** | Преподаватели — подразделения; студенты — дисциплины | **Напрямую нельзя.** Нужна доп. таблица с двумя FK и составным PK (*Трудоустройства*, *Результаты освоения дисциплины*) |

**Нотация Эвереста:**
- сущность — прямоугольник, атрибуты внутри, связь — линия с глаголом;
- концы линии: `O<` ноль или более, `|<` один или более, `|` только один, `O|` ноль или один;
- 1:1 — черта на обоих концах; 1:N — черта и «воронья лапка».

## 4. Пример из ЛР (учебная БД)
- **Сущности:**
  - Студенты;
  - Студенческие билеты (вынесены отдельно: даты относятся к документу, а не к человеку);
  - Студенческие группы;
  - Структурные подразделения;
  - Преподаватели;
  - Дисциплины;
  - Результаты освоения дисциплины (N:N студенты — дисциплины, оценка 2–5);
  - Трудоустройства (N:N преподаватели — подразделения, номер договора, ставка).
- **Связи:**
  - 1:1 — Студенты — Билеты;
  - 1:N — Группы → Студенты, Подразделения → Группы, Подразделения → Дисциплины, Преподаватели → Дисциплины.

## 5. Команды
```sql
CREATE TABLE [IF NOT EXISTS] имя ( столбец тип [ограничения], ..., [ограничения таблицы] );

ALTER TABLE student ADD COLUMN address varchar(30);          -- добавить столбец
ALTER TABLE student ALTER COLUMN address TYPE varchar(80);   -- изменить тип
ALTER TABLE student ALTER COLUMN address SET DEFAULT 'нет';  -- / DROP DEFAULT
ALTER TABLE student DROP COLUMN address;                     -- удалить столбец
ALTER TABLE t ADD CONSTRAINT имя CHECK (...);                -- / DROP CONSTRAINT имя

DROP TABLE [IF EXISTS] имя [CASCADE | RESTRICT];
```
- `IF EXISTS` — если объекта нет, только замечание, а не ошибка.
- `CASCADE` — удалить и зависимые объекты.
- `RESTRICT` — отказ, если есть зависимые объекты (**по умолчанию**).

## 6. Ограничения
| Ключевое слово | Пример |
|---|---|
| `PRIMARY KEY` | `structural_unit_id SERIAL PRIMARY KEY` / `PRIMARY KEY(a, b)` |
| `FOREIGN KEY ... REFERENCES` | `FOREIGN KEY(gr) REFERENCES groups(gr) ON DELETE CASCADE` |
| `REFERENCES` (FK из одного столбца) | `unit_id INTEGER NOT NULL REFERENCES structural_units(structural_unit_id)` |
| `NOT NULL` / `NULL` | `birthday DATE NOT NULL`, `patronymic VARCHAR(30) NULL` |
| `UNIQUE` | `email VARCHAR(30) UNIQUE` |
| `CHECK (условие)` | `mark INTEGER NOT NULL CHECK (mark >= 2 AND mark <= 5)` |
| `DEFAULT` | `valid BOOLEAN DEFAULT TRUE` (без DEFAULT значение по умолчанию — NULL) |
| `CONSTRAINT имя` | `CONSTRAINT email_check CHECK (email ~* '...')` |

- `UNIQUE` + `NOT NULL` по свойствам ≈ PK, но **PK один**, а UNIQUE и NOT NULL — сколько угодно.
- Все ограничения можно вынести на уровень таблицы. Составные PK и FK задаются только там.
- `ON DELETE CASCADE` — при удалении строки главной таблицы удаляются связанные строки подчинённой.

**Пример из ЛР:**
```sql
CREATE TABLE Student(
    student_id            INTEGER     NOT NULL,
    surname               VARCHAR(30) NOT NULL,
    name                  VARCHAR(30) NOT NULL,
    patronymic            VARCHAR(30) NULL,
    students_group_number VARCHAR(7)  NOT NULL,
    birthday              DATE        NOT NULL,
    email                 VARCHAR(30) UNIQUE,
    PRIMARY KEY(student_id),
    CONSTRAINT Students_group_key FOREIGN KEY(students_group_number)
        REFERENCES Students_group(students_group_number) ON DELETE CASCADE,
    CONSTRAINT email_check
        CHECK (email ~* '^[A-Za-z0-9._+%-]+@[A-Za-z0-9.-]+[.][A-Za-z]+$')
);
```

**Регулярки:**
- операторы: `~` — с учётом регистра, `~*` — без учёта регистра;
- `^` / `$` — начало / конец строки;
- `[0-9]` — цифра, `{n}` — ровно n раз;
- спецсимволы экранируются: `\(`, `\+`.

## 8. Ключевые отличия
| Что сравниваем | Отличие |
|---|---|
| Логическая и физическая модель | Логическая не зависит от СУБД (ER-диаграмма); физическая — под конкретную СУБД (SQL). N:N есть только в логической |
| Сущность / атрибут / связь | Объект / его свойство / отношение между объектами |
| PK и UNIQUE | PK один, без NULL; UNIQUE может быть много, NULL допустим |
| PK и FK | PK идентифицирует запись своей таблицы; FK ссылается на PK главной, может повторяться |
| Главная и подчинённая таблица | Главная — та, на которую ссылаются (сторона «1»), создаётся первой; подчинённая содержит FK (сторона «N») |
| Естественный и суррогатный ключ | Со смыслом (номер билета) / без смысла (`SERIAL`, код) |
| Ограничение столбца и таблицы | В строке столбца / отдельной строкой; составные — только на уровне таблицы |
| `REFERENCES` и `FOREIGN KEY ... REFERENCES` | Короткая форма для FK из одного столбца / полная форма (нужна для составного FK) |
| `ON DELETE CASCADE` и `DROP TABLE ... CASCADE` | Первое удаляет **строки** подчинённой таблицы при `DELETE`; второе удаляет **зависимые объекты** (FK-ограничения, представления), но не сами подчинённые таблицы |
| CASCADE и RESTRICT | Удалить с зависимыми / отказать (по умолчанию) |
| DROP TABLE, DROP COLUMN, DELETE | Таблица целиком / один столбец / строки (структура остаётся) |
| `IF EXISTS` и `IF NOT EXISTS` | При удалении или изменении / при создании |
| `~` и `~*` | С учётом / без учёта регистра |
| CHAR(n), VARCHAR(n), TEXT | Ровно n символов / до n / без ограничения |

## 9. Ответы на контрольные вопросы
1. **Зачем проектирование?**
   - Чтобы выбрать логическую структуру данных: таблицы, атрибуты, ключи, связи, ограничения.
   - Чтобы перевести её в форму для конкретной СУБД.
   - Это убирает дублирование и обеспечивает корректность данных.
2. **Что такое ER-модель?**
   - Модель «сущность–связь»: графическое представление структуры БД.
   - Диаграмма состоит из сущностей, атрибутов и связей (в ЛР — нотация Г. Эвереста).
3. **Типы связей:**
   - **1:1** — студент и студенческий билет;
   - **1:N** — группа и студенты, самая частая;
   - **N:N** — преподаватели и подразделения.
4. **Как реализовать N:N?**
   - Через дополнительную (ассоциативную) таблицу с внешними ключами на обе таблицы.
   - Эти ключи обычно образуют составной PK.
   - Пример: *Трудоустройства* (`employments`).
5. **Команды ограничений:** `PRIMARY KEY`, `FOREIGN KEY ... REFERENCES`, `NOT NULL` / `NULL`, `CHECK`, `UNIQUE`, `DEFAULT`, `CONSTRAINT имя`.
